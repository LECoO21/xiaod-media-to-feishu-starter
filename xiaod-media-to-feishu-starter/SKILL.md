# 小D链接转文档·小白版

## 首次使用

先运行 `xiaod-doctor`。若有未完成项，读取 [setup.md](references/setup.md)，只让用户配置缺失的模型服务或飞书 CLI；其余安装和操作由 Agent 完成。

禁止读取、打印、复制或保存用户的密钥、Token、Cookie、应用标识、账号标识、资源标识和授权链接。禁止在 Skill 中固化任何个人路径或账户配置。只调用本机已配置的 CLI，不编写原始网络请求。

## 运行原则

- 每个任务使用 `work/<job-id>/`，最终稿写入 `outputs/<title>.md`。
- 在 `work/<job-id>/status.json` 记录来源、当前阶段和已生成文件；每完成一步立即更新。中断后从最后成功阶段继续，不重复下载、转录或写远端。
- 主动执行流程，不让小白复制命令。只有登录、授权或受限内容需要用户本人处理。
- 运行超过一分钟时简短报告当前阶段。文件或模型缓存持续增长表示仍在工作；连续五分钟无增长才判定卡住。

## 工作流

### 1. 识别来源

记录来源、标题、时长、语言、访问条件和交付要求。优先级固定为：人工或官方逐字稿/字幕 → 飞书已有转录 → 平台自动字幕 → 本地 ASR。简介和章节只用于核对元数据、术语和主题，不能代替正文。

飞书逐字稿先读取目录。遇到“关键词 / 文字记录”结构时，按飞书 CLI 自带的最新指南获取完整 Markdown，保存到当前任务目录；不要把长正文刷入聊天。

### 2. 获取文本或转录

按需使用：

```bash
xiaod-media-pipeline inspect SOURCE
xiaod-media-pipeline subtitles URL --output-dir work/JOB/source
xiaod-media-pipeline youtube-transcript URL --output-dir work/JOB/source
xiaod-media-pipeline download URL --output-dir work/JOB/source
xiaod-media-pipeline convert INPUT --output work/JOB/source/asr-input.wav
xiaod-media-pipeline transcribe INPUT --output-dir work/JOB/asr --language zh
```

- 只处理公开或用户明确授权的单条内容；不加载浏览器凭据，不绕过登录、付费、DRM、地域或私密分享限制。
- 本地文件先检查，不复制原件；仅在 ASR 需要时转成单声道 WAV。
- 使用安装器配置的本地默认模型。模型下载停滞时保留缓存并重试一次；仍失败则换用已配置的轻量模型，不清空缓存。
- 保留原始 TXT/JSON 转录直到整个任务完成，不覆盖唯一原始结果。

### 3. 分享式提纯

生成“分享式提纯版原文”，不是摘要：

- 删除时间戳、说话人标签、寒暄、口水话、噪音、重复和残句。
- 核对人名、公司、产品、地名、术语、缩写、日期和数字；不确定项标记待核对，不猜。
- 保留原意、语气、案例、数字、类比、限定条件、判断链和重要原话。
- 先建立少量大主题，再逐段提纯；分块后全局去重并恢复跨段逻辑。
- 标题具体且来自正文。禁止“一句话总结”“核心要点”“启发”“结论”“其他有效观点”“补充说明”等摘要式标题。
- 不新增事实、不外推、不替原文下结论；重要判断适度加粗。

### 4. 本地验收

```bash
xiaod-media-pipeline qc outputs/成稿.md
```

自动检查通过后，再人工核对案例、数字、专名、标题密度、乱码、重复和跨段逻辑。未通过时只修本地稿，不创建飞书文档。

### 5. 飞书交付

- 只使用 `lark-cli-user`，并先读取该 CLI 自带的当前操作指南；不要使用未配置的内置飞书工具，也不要自行重新绑定或登录。
- 从工作区内的相对 Markdown 路径创建或覆盖文档，默认迁入名为“音视频转录整理”的知识库；不要固化知识库标识。
- 异步迁移必须等到完成。随后回读目录，检查标题层级、空标题、重复标题和正文结构，再用同一用户身份验证知识库链接可访问。
- 创建、入库、目录和访问任一步未验证，都不得声称完成。授权失效时只告诉用户需要重新登录，不要求粘贴凭据或全文。

### 6. 清理中间文件

仅当本地 QC、飞书入库、目录回读和访问验证全部成功后执行：

```bash
xiaod-media-pipeline cleanup work/JOB --output outputs/成稿.md --wiki-url "已验证链接"
xiaod-media-pipeline cleanup work/JOB --output outputs/成稿.md --wiki-url "已验证链接" --apply
```

先预览，再删除。只清理 `work/` 的一个直接子目录；拒绝共享目录、根目录和符号链接。保留最终 Markdown；失败或未验证时保留全部中间文件。

## 回复格式

- **完成**：只给必要质量说明、释放空间和知识库链接。
- **部分完成**：说明最后成功阶段、失败阶段和唯一下一步；继续时不重做前序步骤。
- **阻塞**：说明真实错误类型和用户需要完成的一个动作，不堆叠多种方案。
